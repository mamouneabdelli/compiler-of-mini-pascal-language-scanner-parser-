01 The Compiler Pipeline

A compiler front-end transforms raw source text into a structured, validated representation through two cooperating stages.

The Scanner never looks at grammar rules — it only groups characters into the smallest meaningful units, called tokens. The Parser never looks at individual characters — it consumes the token stream and checks whether it matches the structure defined by the language's grammar.

02 BNF Notation

Backus Normal Form (BNF) is the formal notation used to describe the MP-FR grammar. Every rule defines a non-terminal in terms of terminals and other non-terminals.

::="is defined as"<NomType> ::= entier
<Nom>Non-terminal — a symbol expanded by another rule<NomVariable>

Reading a rule like <DéfinitionConstante> ::= <NomConstante> = <Constante> ; tells the parser exactly what sequence of tokens to expect: an identifier, then the literal =, then a constant, then a semicolon.

03 Lexical Analysis (Scanner)

The scanner reads the source file character by character and groups characters into tokens — the smallest units that carry meaning.

Token categories in MP-FR

Keywords

Reserved French words with fixed meaning: programme, debut, fin, si, alors, sinon, tantque, pour, repeter, jusqu'a, entier, reel, et, ou, div, mod.

Identifiers

Names for variables, constants, and the program itself. Defined by <Nom> ::= <Lettre> <Chiffre> {<Lettre> | <Chiffre>} — a letter/digit pair followed by any mix of letters and digits.

Numbers

Integer literals (123) or decimal literals (3.14), matched by the <Nombre> rule.

Operators & punctuation

Assignment :=, relational operators (=, <>, <=, >=...), arithmetic operators (+ - * div mod), and separators like ; , : .

What the scanner produces

  • TOKEN file — every token in order, tagged with its category (e.g. KEYWORD(programme), IDENT(x), NUM(5), OP(:=)).
  • Symbol table — every identifier the scanner has seen, used later for type checking and to detect undeclared variables.
  • Lexical errors — characters or sequences that don't form a valid token (e.g. an unterminated identifier, an invalid number format, or an unrecognized symbol).

04 The Symbol Table

A running record of every identifier the scanner has encountered, along with metadata used by later compilation stages.

NameKindTypeFirst seen

Each time the scanner meets a name it hasn't seen before, it inserts a new entry. If the same name appears again, the scanner reuses the existing entry instead of duplicating it — this is how the parser later knows whether a variable was actually declared.

05 Syntax Analysis (Recursive Descent Parser)

The parser consumes the token stream produced by the scanner and checks it against the MP-FR grammar, one rule at a time.

How recursive descent works

Each non-terminal in the grammar becomes a function in the parser. A function for <Instruction> looks at the current token to decide which alternative to try (si → call the function for <InstructionSi>, tantque → call the function for <InstructionTantque>, an identifier → call the function for <InstructionAffectation>, and so on). Each function may call other functions, mirroring the structure of the grammar — hence "recursive descent": the parser descends through the grammar tree, recursively, following the shape of the program.

What the parser produces

  • RULE file — the ordered list of grammar rules applied while parsing, forming a derivation of the program.
  • Syntax errors — reported when the current token doesn't match what the active rule expects (e.g. alors missing after a condition, or a missing ; between statements).

Expression precedence

MP-FR expressions are layered so that operator precedence falls out of the grammar structure itself, without needing extra logic: 

<Expression>       → comparisons (=  <>  <  >  <=  >=)
  └─ <ExpressionSimple> → addition / subtraction / ou
       └─ <Terme>          → multiplication / div mod et
            └─ <Facteur>     → constants, variables, ( <Expression> )

Because each level can only be reached through the level above it, * always binds tighter than +, which always binds tighter than a comparison — exactly the precedence rules of ordinary arithmetic.

06 MP-FR Grammar Tree

A simplified view of how a full MP-FR program decomposes into its grammar rules, from the program declaration down to individual instructions.

  • ProgrammePascal
    • programme NomProgramme ;
    • Corps
      • PartieDéfinitionConstante (optional)
        • DéfinitionConstante → NomConstante = Constante ;
      • PartieDéfinitionVariable (optional)
        • DéfinitionVariable → GroupeVariable ;

        • debut
        • Instruction {; Instruction}

Grammar rules applied (excerpt)

  1. ProgrammePascal → programme NomProgramme ; Corps .
  2. Corps → PartieDéfinitionVariable InstrComp
  3. PartieDéfinitionVariable → variable DéfinitionVariable
  4. DéfinitionVariable → GroupeVariable ;
  5. GroupeVariable → NomVariable , NomVariable : NomType
  6. InstrComp → debut Instruction { ; Instruction } fin
  7. Instruction → InstructionAffectation (x := 5)
  8. Instruction → InstructionSi
  9. InstructionSi → si Expression alors Instruction sinon Instruction
  10. Expression → ExpressionSimple OperateurRelationnel ExpressionSimple (x <= 10)

08 Glossary

Token

A categorized chunk of source text — the output unit of the scanner (e.g. keyword, identifier, number, operator).

Lexeme

The actual text matched for a token, e.g. the lexeme x for an identifier token.

Non-terminal

A grammar symbol that expands into other symbols, written <LikeThis>.

Terminal

A literal symbol that appears directly in the source code and cannot be expanded further (keywords, punctuation).

Derivation

A sequence of grammar rule applications that transforms the start symbol into the actual program text.

Recursive descent

A top-down parsing technique where each grammar rule is implemented as a function that may call other rule-functions.
